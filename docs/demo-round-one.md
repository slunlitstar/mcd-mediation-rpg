# 第一轮 Demo：范围与交接

## 启动与演示

根目录执行 `npm run dev:web`，打开 Vite 输出的地址（默认 http://127.0.0.1:5173/）。
第一轮完全在浏览器本地运行，无需服务端、凭据、AI 或 MCP。
首页「体验三人示例」会填入可编辑的示例，随后仍按五页流程体验。
状态保存在当前 React 会话中：页面内前进、返回会保留；刷新浏览器会重置。

## 已实现的五个界面

1. 调解所大厅：开始饭局、体验三人示例、定稿餐袋调解官紧凑展示。
2. 小队集结：2—4 人、示例门店选择。没有公共预算、房间、邀请或昵称。
3. 职业与属性：成员1—4、角色浏览与明确选用、独立个人预算、饥饿程度、喜欢／不喜欢、不可退让要求。
4. 仲裁庭：按实际输入展示角色诉求；模拟阶段动画后执行本地示例算法。
5. 饭局结局：和平／省钱／快乐策略、餐品分配与价格、接受确认、弹窗复议。无真实下单。

个人预算初始为空，第一版支持 1—200 元整数；人数默认为三人，可改为两人或四人。
饥饿程度固定为「有点饿／很饿了／饿晕了」。角色选择不覆盖手动填写的属性。
不喜欢的品类在本轮直接排除；新增喜欢会移除同品类的不喜欢，反之亦然。
不可退让要求支持预设选项和「其他（自己填写）」。选择其他时显示 120 字以内的输入框，不能为空或只有空格。
自填内容按成员保存并出现在调解气泡与结果卡中；切换成员或选项后保留原文。
本地示例算法不解析自填文本，结果用 `requiresManualReview` 明确标记待核对，不将其冒充为已满足。
有自填要求时，接受方案前需勾选已逐项核对；更换策略或重新生成后清除核对状态。
角色只在首次、偏好尚未编辑时预填建议。预算与饥饿程度始终由用户自行确认。
减少人数会移除末尾成员，增加人数会新增空白成员；相同角色可重复选择。

## 素材与数据

- `apps/web/src/assets/characters/originals/`：五张已确认原图，按角色命名，文件内容完整保留。
- `apps/web/src/assets/characters/selected/`：四张基于原图编辑并确认的选中姿态，第三页切换展示并保留轻微浮动。
- `apps/web/src/assets/characters/character-assets.ts`：原图地址、尺寸、替代文字与显示位置的统一映射。
- `apps/web/src/components/CharacterArtwork.tsx`：共用定稿角色图，支持选角、头像、调解员、异常状态等显示尺寸；原文件不裁切、不拉伸。
- `apps/web/src/styles/character-creation.css`：第三页的角色比例与控件精修样式。
- `apps/web/src/styles/theme.css`：五页面统一的奶油白、暖麦黄、深番茄红配色层；见 [配色说明](ui-theme.md)。
- `apps/web/src/components/Character.tsx`：兼容旧调用的轻量转发组件，使用同一套定稿原图，不再绘制旧占位角色。
- `apps/web/src/styles/cross-page.css`：定稿素材应用到其他页面的手机布局、头像、紧凑首页和状态卡。
- `apps/web/src/services/demo-data.ts`：虚构门店、商品、价格、角色与标签。所有策略共用这份目录，不冒充真实麦当劳数据。
- `apps/web/src/services/demo-service.ts`：本地服务边界，接收饭局、返回结构化方案；此处之后对接后端。
- `apps/web/src/types/demo.ts`：第一版类型，作为双方对齐字段的起点。

第三页已替换四个角色占位图，保留成员1—4、独立预算、饥饿程度原文和其他自填要求。
个人预算初始仍为空；20／25／30／40 元按钮仅作为可选快捷填写，不是公共预算或默认值。
角色图的选择与浏览分开，重复点击已选用角色不会清除成员配置状态。
五个页面已复用定稿素材。调解员统一为「袋袋调解官」，旧小票和食物占位绘图已替换。
首页使用紧凑餐袋介绍，首页五人合照仍作为后续独立素材任务；小队集结页改用紧凑共用提示，不再显示大幅占位餐袋。
仲裁庭使用成员定稿图与可展开完整诉求；结果页使用对应头像。接受、复议和失败状态也使用同一餐袋形象。
详见素材目录内的 README。页面 CSS 对图片进行背景融合，不改变原文件。

金额运算用整数分；每位成员分别检查预算、食物限制、必须包含项和示例饱腹权重。
菜单组合上限为每人 5 份，同品类通常最多 1 份，汉堡最多 2 份。
饱腹权重属于演示规则，不是营养数据或真实吃饱保证。
本轮无优惠、配送费、包装费、库存、营业时间、跨店价格或套餐拆分计算。
策略可能得到相同组合；无解时提示修改，不自动突破预算或硬性条件。
复议可针对一个成员要求省钱、提高饥饿程度、优先安排汉堡／薯条／饮料。
提高饥饿程度会更新该成员属性；新增偏好保留原硬性条件，遇到排除项会提示先修改。
没有更便宜的组合时如实说明，不编造价格变化。

## 后端交接建议（接口尚未实现）

先由后端验证工具能力和所需授权，再确认正式接口；这些是前端期望，不代表 MCP 已支持。

| 需求 | 当前来源 | 后端需要补齐 |
| --- | --- | --- |
| 门店列表 | `stores` 常量 | 稳定门店 ID、名称、地址；缺少能力时商议选择方式 |
| 商品目录 | `products` 常量 | 商品 ID、名称、价格（整数分）、品类、可用图片；食材信息缺失时不能声称已验证忌口 |
| 方案生成 | `generateDemoPlans(request)` | 根据门店与成员需求返回可核算的方案、分配与解释 |
| 复议 | 同一服务＋结构化 `revision` | 基于当前需求和上一方案调整，保留其余成员限制 |
| 失败 | `issues` 数组 | 区分数据不可用、输入冲突和无可行组合，提供可展示原因 |

输入结构：

```json
{
  "party": {
    "storeId": "demo-campus",
    "members": [
      { "id": 1, "roleId": "saver", "budget": 25, "hunger": "little", "likes": ["burger"], "dislikes": [], "requirement": "no-spicy", "configured": true },
      { "id": 2, "roleId": "hungry", "budget": 35, "hunger": "faint", "likes": ["burger"], "dislikes": [], "requirement": "none", "configured": true }
    ]
  }
}
```

`budget` 单位是元；输出 `priceCents`、`totalCents` 单位是分。`configured` 只用于前端进度。
成员新增 `customRequirement: string`（默认空字符串），仅在 `requirement: "other"` 时作为当前自填要求使用。
分配项新增 `requiresManualReview: boolean`，用于区分待人工核对的自填要求；后端接入后需按真实校验能力返回状态。
`issues[]` 支持可选的 `kind: "input" | "constraint" | "unavailable"`。输入缺失或条件无解时引导修改对应成员；临时不可用时提供重试。
未提供类型的旧问题默认按需要调整的条件展示；后端联调时请为临时错误明确传 `unavailable`。
结果包括 `plans[]` 与 `issues[]`。每套方案含 `strategy`、`allocations[]`、`totalCents`、`explanations[]`。
分配项含 `memberId`、`items[{productId,quantity}]`、`totalCents`、`matchedLikes`、`missingLikes`、`reason`。
正式后端接入时需共同扩展来源标记与商品目录返回，替换当前 `productFor`／`stores` 目录查询；不能只把真实商品 ID 塞进示例目录。
MCP 配置与凭据只留在服务端；不要放进前端变量、提交或示例结果。

```sh
npm run check

```

测试复用项目已有的 `tsx` 开发依赖，覆盖金额对账、2／4 人、不同饥饿程度、硬性限制、无解、复议和自填要求。
界面验收：从空白饭局完成全流程；从三人示例完成策略切换、接受和复议；预算 1 元时显示无解；返回后数据保留；窄屏可操作。

本轮已加入角色选中反馈、仲裁庭阶段轨迹与个人预算条，详见 [动态与可视化](ui-motion.md)。
类型检查与生产构建通过，11 项逻辑测试通过；前次本机预览 HTTP 返回 200。
浏览器自动化访问被环境策略拦截，因此上述界面验收清单仍需在本机浏览器中人工确认，尚未完成截图或移动端视觉验收。

手机端已调整为默认布局（`styles/mobile.css`），320px 起支持单列，960px 起扩展为电脑布局。
角色卡合并为紧凑立绘与介绍，成员切换栏可吸顶；属性字号、预算滑条、选择按钮、商品金额均按手机阅读和触控调整。
配置页与结果页有底部操作栏并预留页面空间和安全区；检测到 iOS 键盘收起视觉视口时暂时隐藏操作栏。
结果先显示总价、餐品与分配，已移除整块推荐理由展开区；自填要求待核对时底部按钮可定位到核对选项。
复议在可滚动的底部弹层完成，不新增页面。真机浏览器与软键盘行为仍待实测。

同一可信 Wi-Fi 下执行 `npm run dev:mobile`，手机打开终端打印的当前 Wi-Fi `Network` 地址。
该命令监听网络接口用于局域网联调，默认 `dev:web` 保留本机监听。电脑的 `127.0.0.1` 地址不能直接用于手机。
