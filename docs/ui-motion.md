# 第一轮动态与可视化

## 范围

使用现有定稿原图、基于原图编辑并确认的四张选中姿态与本地示例数据，未新增动画库。配色与手机优先布局沿用当前版本。

1. 角色页：左右浏览时方向一致的短平移；选中后切换为举手、跳跃、眨眼等更明显的定稿姿态，并保留一次小幅上浮、确认标记和当前角色的轻微呼吸起伏。
2. 仲裁庭：诉求依次呈现；顶部显示当前阶段与四段阶段轨迹；调解员台词随阶段切换；下方提供完整阶段说明。
3. 结果页：每位成员显示实际花费／个人预算、预算使用条、剩余金额。切换策略时预算条按真实数值过渡。

`styles/motion.css` 集中维护动效；角色原图没有被修改。表情与动作变化通过切换静态姿态图呈现，轻微浮动通过 CSS 实现。
仅预载当前浏览角色的选中姿态，加载完成前保留原图；两种状态使用相同尺寸与裁切位置，切换不挤动属性或按钮。
结果页移除整块「偏好匹配与推荐理由」展开内容；计算规则与服务返回的理由字段保留，预算和自填要求核对提示继续展示。

## 仲裁庭行为

保留自动进入结果的默认流程，约 3 秒完成示例演示；页面明确标记示例模式。
在核对阶段实际调用本地 `generateDemoPlans`，拿到结果后即可点击「跳过演示，看方案」。
若出现输入问题、条件无解或生成失败，直接进入对应调整／失败状态，不将后续阶段标记为全部成功。
触摸页面或将键盘焦点移入页面时停留查看，阶段继续推进；完成后由用户点击「查看方案」。
返回、离开页面或重新开始时清理旧定时器并忽略旧结果，不让旧请求带着用户跳页。
当前阶段轨迹是本地演示的呈现节奏，不代表 MCP／AI 正在实时执行；后端接入后应将状态与实际事件对齐。

## 手机与减少动态

- 手机顶部有简短当前阶段，避免只能滚到页面底部才知道进度。
- 底部按钮始终可达，可查看成员完整诉求；没有必须等待的长动画。
- `useElementVisibility` 暂停离屏或后台标签页中的角色待机动作。
- 预算条首次可见时展开，之后切换策略平滑更新；离屏时直接更新数据，不持续插值。
- `prefers-reduced-motion` 下关闭平移、呼吸、脉冲及预算条过渡，缩短演示延时。
- 动画不修改预算、成员诉求或方案金额，不增加虚构的满意度分数。

## 预算计算

`services/budget-usage.ts` 将个人预算的元转换为整数分，与 `totalCents` 比较。
预算条视觉宽度最高为 100%；超出时仍明确显示超出金额；缺失／无效金额不显示虚假的预算确认。
可访问性 meter 提供实际花费、个人预算与剩余／超额信息，数值文本不随动画滚动。
